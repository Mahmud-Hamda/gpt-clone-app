# GPT Clone — Full-Stack Web Dev Assistant

A ChatGPT-style chat app built with **React + Vite** on the frontend and **Node.js + Express** on the backend. Conversations are stored in **MySQL**, and answers are generated by **Google Gemini**. The assistant is scoped to full-stack web development questions and politely declines anything off-topic.

**Live demo:** [gpt-clone-tau-sable.vercel.app](https://gpt-clone-tau-sable.vercel.app)

![Architecture](docs/architecture.png)

## Features

- ChatGPT-like UI: sidebar, header, message list and input box
- Markdown rendering of assistant answers
- Chat history persisted in MySQL and reloaded on page load
- Private history per visitor: each browser gets an anonymous session id, and only sees its own messages
- Recent messages from the same session are sent to Gemini as context, so follow-up questions work
- System prompt restricts the assistant to web development topics
- Per-IP rate limits and a question length cap protect the Gemini quota

## API

Base URL: `/api`

| Method | Endpoint         | Body                    | Description                                                    |
| ------ | ---------------- | ----------------------- | -------------------------------------------------------------- |
| GET    | `/health`        | —                       | Health check                                                   |
| GET    | `/chat/messages` | —                       | Returns the session's most recent messages (oldest first)      |
| POST   | `/chat/messages` | `{ "question": "..." }` | Asks Gemini, stores the question and reply, returns both       |

Responses use the shape `{ success, message, data }`. A successful `POST` returns `201` with `data: { userMessage, assistantMessage }`.

**Sessions.** Every `/chat` request needs an `X-Session-Id` header containing a UUID. The frontend generates one per browser and keeps it in `localStorage`; it is not a login and identifies nobody. Each session only reads and extends its own history.

**Limits.** Per IP: 60 API requests a minute, plus 5 questions a minute and 50 a day. Questions are capped at 2,000 characters. Over a limit, the API returns `429` with a readable `message`. Counters are in memory, so on Vercel each warm function instance counts separately.

**Gemini errors.** Gemini's own error text is logged, never shown. When the Gemini quota is used up (the key is on the free tier) or Gemini is overloaded, the API returns `503` with a friendly message; other Gemini failures return `502`.

## Getting Started (local)

### Prerequisites

- Node.js 20+
- A MySQL 8 database (local install or Docker)
- A Gemini API key from [Google AI Studio](https://aistudio.google.com/apikey)

### 1. Install dependencies

```bash
npm run install:all
```

### 2. Create the database table

Create a database (e.g. `chatgpt_clone_DB`) and run [`backend/db/schema.sql`](backend/db/schema.sql) against it. If your `conversations` table was created before sessions existed, run the files in [`backend/db/migrations`](backend/db/migrations) instead.

Using Docker, for example:

```bash
docker run -d --name gpt-clone-mysql -p 3306:3306 \
  -e MYSQL_ROOT_PASSWORD=secret -e MYSQL_DATABASE=chatgpt_clone_DB mysql:8
docker exec -i gpt-clone-mysql mysql -uroot -psecret chatgpt_clone_DB < backend/db/schema.sql
```

### 3. Configure environment variables

Create `backend/.env` and `frontend/.env` with the variables listed in [Environment Variables](#environment-variables). Both files are git-ignored.

### 4. Run

```bash
npm run dev
```

This starts both apps:

- Backend: http://localhost:5002
- Frontend: http://localhost:5173

## Environment Variables

### Backend (`backend/.env`)

| Variable         | Description                                                        |
| ---------------- | ------------------------------------------------------------------ |
| `PORT`           | Port for the local server (default `5002`)                         |
| `CLIENT_ORIGINS` | Comma-separated frontend URLs allowed by CORS                      |
| `DB_HOST`        | MySQL host                                                         |
| `DB_PORT`        | MySQL port                                                         |
| `DB_USER`        | MySQL user                                                         |
| `DB_PASSWORD`    | MySQL password                                                     |
| `DB_NAME`        | MySQL database name                                                |
| `DB_SSL`         | `true` for hosted MySQL that requires TLS                          |
| `DB_SSL_CA`      | CA certificate (PEM) if your provider uses its own CA, e.g. Aiven  |
| `GEMINI_API_KEY` | Google Gemini API key                                              |
| `GEMINI_MODEL`   | Gemini model name (default `gemini-3.5-flash-lite`)                |

### Frontend (`frontend/.env`)

| Variable            | Description                                         |
| ------------------- | --------------------------------------------------- |
| `VITE_API_BASE_URL` | Backend API base URL, e.g. `https://api.example.com/api` |

## Deployment

The frontend and backend are deployed as **two separate Vercel projects** from this same repository:

| Vercel project | Root Directory | Framework preset |
| -------------- | -------------- | ---------------- |
| Backend        | `backend`      | Express          |
| Frontend       | `frontend`     | Vite             |

The backend needs a MySQL database reachable from the internet. The live demo uses a free [TiDB Cloud Starter](https://tidbcloud.com) instance (MySQL-compatible, `DB_SSL=true`, port `4000`) in AWS `us-east-1`, with the backend's Vercel function region set to `iad1` to match. Set the backend environment variables in the backend Vercel project, set `VITE_API_BASE_URL` in the frontend Vercel project, and add the frontend URL to `CLIENT_ORIGINS`.
